Scikit-learn:
the working picture.

Scikit-learn is a Python library for machine learning. This page shows the usual order of work, what the main words mean, and how a table of data becomes a prediction.

The central idea

inputs
X→fitted
model→prediction

Known answers y are used while fitting. A prediction ŷ is the model's estimated answer for new inputs.
01

Start with something real

One table. Two different jobs.

Imagine a table of past house sales. Each row is one sale. The first three columns are facts available before the sale. The final column is the answer we already know.

Example dataset: past house sales. Use this same table as you read the rest of the guide.

Plain-English rule: a row, example, instance and observation usually mean the same thing here: one item of data presented to the model. A feature is an input. A target or label is the answer.

02

The order of work

The main scikit-learn workflow.

Do these stages in this order. You will revisit the middle stages while improving a model, but the basic shape stays the same.

1 · DefineAsk a clear question

What answer do you need: a number, a category, or groups?

2 · PrepareBuild the dataset

Decide what one row means, which columns are inputs, and whether an answer is known.

3 · ProtectSplit the data

Keep some examples aside before fitting, so you can test fairly later.

4 · LearnFit a model

Give it known input-and-answer pairs. It learns a pattern from them.

5 · CheckEvaluate it

Compare its predictions with answers it did not see during fitting.

6 · UsePredict on new data

Supply new inputs. The fitted model estimates an answer.

03

Choose the kind of answer first

The task narrows the model.

You do not begin by scrolling through hundreds of scikit-learn classes. First identify the output you need. That tells you which broad family of tools is relevant.

Known numeric answer

Regression

Estimate a quantity, such as a sale price, temperature or delivery time.

Output: number

Known category answer

Classification

Choose a class, such as spam/not spam, species, or a letter.

Output: class

No supplied answer

Clustering

Find groups of similar rows when no correct group label has been provided.

Output: group ID

Labelled does not mean “good” and unlabelled does not mean “bad”. Labelled data has a known target, so it can teach a supervised model. Unlabelled data has inputs but no supplied answer; it can still be useful for clustering and later prediction.

04

Name the parts without mixing them up

Algorithm, estimator, model, prediction.

These words describe different parts of the same process. Keeping them separate stops scikit-learn from feeling like a pile of mysterious commands.

General method

Algorithm

A method for finding a useful pattern in data. For example, a method that fits a straight line.

↓implemented as
Scikit-learn object

Estimator

The Python object you use, such as LinearRegression(). Before fitting, it has not learned from your data.

What fitting does

Learn parameters

Fitting uses training examples to find values that describe a pattern, such as a line's slope.

→produces
Data-specific result

Fitted model

The estimator after .fit(X, y). It can now make predictions for new inputs.

One sentence to keep: an algorithm is the general method; an estimator is the scikit-learn object; a fitted model is that object after it has learned from your training data; a prediction is its output for new inputs.

05

Do not mark your own homework

Check the result on held-back data.

A model can memorise training rows and look impressive without being useful. Keep some rows aside before fitting, then use them to check whether the learned pattern works on unseen examples.

Used while learning

Training data

These known input-and-answer pairs are supplied to fit(X_train, y_train).

Held back until later

Test data

Use these only after choices are made, to judge likely performance on new data.

Measure the right error

Metrics

Regression often uses MAE or RMSE. Classification may use precision, recall or F1. The useful measure depends on the cost of mistakes.

Keep the boundary clean

Leakage

If held-back answers influence preparation, tuning or model choice too early, the final score is no longer a fair test.

06

A pipeline is not the last step

It keeps preparation and modelling together.

Real data often needs work before a model can use it: fill missing values, scale numbers, or turn categories into usable values. A scikit-learn pipeline stores that preparation alongside the model.

One reusable pipeline
FirstPrepareFill gaps, scale numeric columns, or encode categories.
→
ThenFit the modelLearn from prepared training data and known targets.
→
LaterPredictApply the same preparation to new inputs before predicting.

Why this matters: it prevents you from preparing training data one way and new data another way. The pipeline is a container around this part of the workflow. It may be saved after you trust it.

07

The code follows the picture

Read a simple regression example.

This is a complete, small example. Its point is not to memorise it yet; it is to show where the code fits in the visual workflow above.

# Inputs X: study hours
# Known answers y: exam scores
from sklearn.linear_model import LinearRegression

X = [[1], [2], [3]]
y = [2, 4, 6]

model = LinearRegression()
model.fit(X, y)
prediction = model.predict([[4]])

print(prediction)  # [8.]

What each line is doing

  1. Import: bring in one specific estimator from scikit-learn.
  2. Set up X and y: three known input-and-answer pairs.
  3. Construct: create an unfitted LinearRegression estimator.
  4. Fit: learn the relationship in the known pairs.
  5. Predict: estimate the score for four study hours.

The question to ask when you meet a new scikit-learn class

  • Which stage of the workflow does it help with?
  • Does it prepare data, learn from data, make a prediction, or measure a result?
  • What shape of input does it expect, and what does it return?
